一问 道 二炼 丹 三藏 丹 阁 四模 型

这座炉子也是一件上下文资产：换一个 Agent、换一台机器来接手，它该照样能重建出来， 而不是被重新理解一遍、然后再误一次。
所以按 MRS-EV 太极·点圆统一模型 v1.1 给自己立了规矩—— 丢得掉的写在圆上，丢不掉的收在点里，见不得人的交给 Vault。 下面这张图，说的是同一件事。

数 据 也 分 点 圆
八十一章数据看上去是一个文件，其实两种命
段为何切在哪一层
chapters[].original / title / themes / keywords 原典事实，没有第二处为真 内核
detail.*.benyi / yinshen / wei / sources 训诂与判词，里面有人的取舍 内核

一句话记住这一刀：怎么判是内核，判出来几分是外延。
所以改火候算法要动内核（须人拍板），重跑一遍分数只是刷新快照（机器说了算）。

炉 子 怎 么 长 大
M 指导 S，S 产生 J，J 蒸馏回 M
M 内核→ S 状态→ J 流水⇢ 候选 [ ]⇢ M 内核

前两步是呼吸（日常），第三步是生长（攒一批才做）。补上它，太极才转得起来。 

python3 scripts/distill.py            # 扫 Journal.md → CANDIDATES.md（只提候选）
# 人在 CANDIDATES.md 里勾选，改成 [x] 后：
python3 scripts/distill.py --apply    # 才落入 Memory.md「熏修所得」

相可以自动，君不可以。脚本绝不自动改内核——它只会把候选端到人面前。 判据是：换一个全新的项目，这条还成立吗？成立才进 M。一次是意外，两次是模式，三次是原则。

一 条 通 路
炉中三位皆是 AI，门只有一个
有 人 来→ 道 童唯一入口→ 丹 师炼化 ／ 炉 灵问道→ 金 丹 · 解 惑

炼化也好、问道也好，先过道童这一关。道童不判、不取，只负责接住与转交—— 判断在 furnace.js（试火），取丹在 ask.js（检索）。 这条通路唯一繁琐的地方，正是它唯一值钱的地方：有一个门，才知道谁进了炉。

八 原 则 · 落 点
不是贴在墙上的，是在代码里找得到的
原则在本炉哪一处兑现
内核不轻动经文一字不改；成丹之文只追加不改；疑则人到
协议先行接手先读 Readme.md；Four questions 答不上不许动手
状态必更新每炼一章回写 refined 与 State.md；藏丹阁计数实时算，不写死 5 和 76
外延可插拔四页各自的 JS 可整片重写；换 UI 不动数据
虚实分离索引与排序是虚（可重算）；金丹是实（人在守）
真值入 Vault课程视频本体不入仓，目录里只留 E3_* 引用名
最小权限零后端、零 CDN、零第三方派发；抓网页只用 credentials:'omit'
泄露即轮换靠换凭证止血，不靠删 git 历史
交 给 下 一 个 接 手 者
交接不是传文件，是传「最小可重建集」
python3 scripts/handoff.py .

生成的 HANDOFF.md 里，内核原样搬运，外延只给索引，真值只给名字。
必须自带验收——接手方能回答四问：是什么／卡在哪／下一步／不能碰什么。 答不上就回问，不许猜。
交接包必须是生成的：手写的必然过期，而过期的交接包比没有更危险——它让接手方以为自己懂了。
