# 授课稿槽位规范（○ E1 外延 · 有价重建立全息）

> 这一处放的是**已经成稿的文字**：课程讲稿、视频转写稿。
> **原始音视频本体不在这里**——它在 Vault 里，这里只留引用名。

## 一、目录惯例

```
assets/media/
  README.md          本文件：放什么、不放什么、怎么取回
  manifest.json      唯一清单：哪一章有什么稿、多大、从哪来
  01/01.course.md        课程文字稿（纯文本，无时间轴）
  01/01.transcript.txt   转写稿（已去时间轴，直接可投料）
  01/01.timed.vtt        保留时间轴的稿子，仅供人读，不喂判定
  08/…
```

章号一律补零两位，与 `data/index.json` 的 `id` 对齐。一号一目录，不混放。

## 二、三种稿子各自什么用

| 文件 | 内容 | 给谁用 |
|------|------|--------|
| `NN.course.md` | 老师授课的手写稿／讲义，可有 Markdown | 人读 + 投料 |
| `NN.transcript.txt` | 视频转写出来并**剥掉时间轴**的正文 | **直接投料** |
| `NN.timed.vtt` | 带时间轴的原始稿 | 只给人核校，不入判定 |

## 三、三条硬规矩

1. **转写稿不带 front-matter。** `INGEST` 不解析 YAML——写了它就把元数据当正文一起炼了。
   一切元数据进 `manifest.json`。
2. **音视频本体不入仓。** 体积大、许可复杂，是真值侧资产（E3／Vault）。
   目录里只出现 `E3_MEDIA_BUCKET` 这样的引用名，不出现地址、账号、密钥。
3. **`has_media` 不许手改。** 它由 `scripts/sync_media.py` 从 manifest 单向回写。
   双向写必漂移，一漂移就没人知道谁是真的。

## 四、怎么入炉

炼丹页已支持 `?src=`：

```
./refine.html?src=./assets/media/01/01.transcript.txt
```

拿到文本 → 剥时间轴 → 填进炉口 → 自动炼化。
藏丹阁与问道页的金丹弹层里，「以此章授课转写稿入炉」走的就是这条路。

浏览器直接拖也可以：`.txt / .md / .srt / .vtt` 拖进炼丹炉，自动识别并清理时间轴。

## 五、取回与留存

- 原始音视频在项目网盘／对象存储，路径见项目 `secrets/README.md` 的引用表。
